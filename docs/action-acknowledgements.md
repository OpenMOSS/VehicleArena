# 请求回执与物理结果

## 驾驶工具

`success=true` 仅表示请求已提交或控制已接受。冻结唤醒批次内返回
`status=queued`，直接提交返回 `status=accepted`。提交后的 command_result
仍是控制提交回执，不是动作完成结论。

换道返回 `target_lane`，移除有歧义的 `lane/new_lane`、计时百分比、
请求时长和提前设置的 `is_changing_lane`。提交回执也不再含 `new_lane`。
可在提交前判断的拒绝直接返回，不计为换道尝试。没有绑定物理后端的
独立驾驶模块返回 `driving_backend_unavailable`，不再用空操作冒充执行。

当前车道和图片仍供模型观察；self_now 不注入换道完成结论或进度。
内部统计也不进入 FrozenStateView。没有新增完成/未完成唤醒事件。

## 内部换道统计

- `lane_change_attempts`：实际通过控制校验的请求次数。排队后被覆盖、
  拒绝或场景初始摆放不算接受的尝试。
- `lane_changes`：实际完成次数。车身全部进入原目标车道，且原生横向
  速度不超过 0.1 m/s 时确认一次；车身边界允许 0.05 m 数值容差。
  SUMO 可以在非居中位置完成，不强制把车辆移动到车道中心。
- `lane_change_uncompleted`：窗口结束且横移已停止仍未进入目标、终态
  中断，或尚未结束的观察被新请求替换。
- `lane_change_pending`：尚未判定的尝试，包括场景结束时仍在执行的请求。

请求窗口默认仍是 3.5 秒。窗口到期只结束请求状态；SUMO 若仍在横移，
继续被动观察直到停下再统计，不延长/重发原生请求，不纠正位置或避险。
横向偏移/速度取原生实测值，窗口到期不再伪造归零。
转向灯、危险换道仍按尝试计分，指标名明确为 `*_lane_change_attempts`。

## 其他工具检查

检查所有 273 个注册工具的 schema，并按返回语义检查以下类别。
这是接口/实现审查加针对性回归，不是穷举所有参数组合的真实 LLM 测试。

| 类别 | 处理 |
| --- | --- |
| 速度、急停、转向、掉头、行人动作 | 回执明确 queued/accepted，不声称完成 |
| 停车查询 | 使用实测速度，不把“要求停车”当成已经停稳 |
| 重新规划、显示目的地变更 | 走真实道路/车道规划；不改变场景任务目的地或控制方向 |
| 地址解析 | 只接受节点 ID、唯一真实地名或已分配目的地名，不偷偷替换成另一目的地 |
| 退出导航 | 关闭显示路线，后续小地图不重新出现旧高亮 |
| 途经点 | 当前无真实多段规划，明确返回 waypoint_routing_not_supported |
| 道路详情 / POI | 运行时拒绝全零占位路况和演示 POI，返回后端/数据不可用 |
| 雷达、图像、限速查询 | 保留实际观测/渲染和只读限速语义，后端缺失不假装取得观测 |
| 空调、车灯、座椅、门窗、多媒体 | 保留同步模块状态变更的成功返回，不错误改为异步物理完成 |
| 工具发现、记忆和待办 | 保留操作完成/明确校验失败语义 |

分配任务时生成的目的地展示名称，同步保存在车辆的 destination_name 中。
地址解析先接受精确节点 ID，再匹配当前车辆已分配的精确名称，最后匹配唯一
地图 full_name；未知地址仍拒绝。避免系统生成的“某路沿线目的地”无法原样
传回导航工具，也避免车辆自己的任务名称被其他节点同名抢占。

旧 cabin-only YAML 的掉头空操作不再被当成“已满足”；物理掉头需要后端
执行和轨迹/Judge 证据，不能用模块快照证明完成。历史轨迹和旧评分不改写。
