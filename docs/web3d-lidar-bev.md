# 同帧 Web3D 局部观察图

正式引擎的可选 `LidarBEV` 已改用 Web3D，保持 `kind=lidar_bev` 和标签兼容，
`view` 更新为 `web3d_ego_oblique`。未安装 lidar 的车辆不新增图片。

![局部三维几何观察示例：本车为蓝色，其他物体为灰色](assets/lidar-bev.png)

示例展示的是从本车后上方观察的处理后几何，不是原始激光点云；图中的颜色用于区分本车与环境，不表示交通灯或天气状态。

## 画面与信息边界

- 1024×1024，35° 相对地面俯角、40° 透视视场角、相机到瞄准点 20 米。
- 本车朝前，地面锚点固定在横向 50%、纵向 75%；完整保留车身。
- 本车车身蓝色 #147bdd，车窗、轮胎深灰，保留部件细节。
- 其他车辆及行人全部网格统一浅灰 #b0b0b0，无车窗/轮胎/车灯颜色区别。
- 道路与建筑使用中性灰；去除颜色贴图、发光、雾、天气、原场景灯光及阴影。
- 固定中性照明只用于呈现几何明暗。没有车速、对象 ID、路线、包围框或 HUD。

平地未被 sensor 配置进一步裁切时，中心纵线前方约 31.5 米、后方约 3.3 米。
透视图横向范围随深度变化，不能按正交地图直接量距离。保持已有 range_m /
horizontal_fov_deg 配置生效：原点在本车，按水平距离和前向扇区裁切；8 米内
保留自车邻近环境，量程仍生效，自车本身始终作为定位参照绘制。

这仍是合成的处理后几何显示，不是从雷达原点发射射线的物理点云，没有
模拟传感器遮挡/噪声。普通 3D 深度遮挡不能代替传感器遮挡；prompt 已明确。

## 接入与资源

车辆帧的 `position_world_xy` 以车身中心为原点（`position_reference=body_center`）。
SUMO 的原始车辆位置是前保险杠中心，Python 渲染编码器沿车身朝向后退半个
车长后再传给 Web3D；前端不要重复偏移。车内相机、侧向视野和 LidarBEV
共用修正后的车辆模型，本车和背景车统一转换，行人坐标保持原样。
该换算只改变显示，不修改 SUMO 位置、碰撞、控制或原始轨迹记录。

MultiSimEngine 在物理/浏览器所属线程调用 `render_observations`，同一辆车
只 encode 一次冻结帧。先保存驾驶图，再用同一页、同一场景、同一物体模型
生成局部图；不启动第二份 SUMO 或浏览器，不多发一个模型调用。最多只有
原来的两张观察图，Judge-only 不渲染。

局部图只编码 WebGL canvas，不截图 DOM。结束或抛异常时恢复材质、照明、
视口尺寸、像素比、背景和渲染器设置。派生材质缓存复用，地图切换时释放。
JS 入口和 Python 均校验时间、帧序号、焦点车辆；explicit focus_entity_id
优先于任何车辆的字面 ID（例如另一个名为 ego 的车辆）。

Web3D JS/HTML/CSS/server 文件纳入实验 source_hash，防止修改图像实现后误用
旧轨迹。原轨迹与原评分不重写，后续运行生成新 manifest。

## 验证边界

浏览器回归覆盖画面、本车定位、整车配色、昼夜天气/车灯不影响局部图、
驾驶图前后逐像素不变、故障恢复、量程/视场配置和缓存复用；引擎回归检查
装备开关、浏览器线程归属和冻结帧复用。此类测试不调用真实 LLM。
